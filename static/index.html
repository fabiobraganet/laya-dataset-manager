01
Visão geral

Comece aqui

O aplicativo conduz um modelo especializado por um fluxo controlado: você organiza exemplos, congela uma versão imutável, treina no Kaggle, valida o checkpoint, publica no Hugging Face e escolhe qual modelo fica ativo no localhost.

1ConfigureConecte Kaggle e Hugging Face.
2PrepareCrie e valide exemplos LAYA.
3TreineEnvie uma versão imutável.
4UseAtive e teste o modelo.
Dica

Comece em Configurações. As duas integrações precisam aparecer como conectadas antes do primeiro treinamento.

02
Preparação

Dataset e exemplos

Um dataset reúne exemplos que ensinam ao LAYA como transformar um estado em respostas estruturadas. Você pode cadastrar exemplos manualmente ou importar um arquivo JSONL. A importação informa a linha, o campo e o motivo de cada erro.

Cadastro manual

Ideal para criar, revisar e corrigir poucos exemplos com controle total.

Importação JSONL

Ideal para lotes. Cada linha deve conter um objeto JSON completo e independente.

Boa prática

Use IDs estáveis e únicos, exemplos variados e textos realistas. Revise os diagnósticos e o painel de qualidade antes de congelar uma versão.

Atenção

Uma versão é imutável. Alterações posteriores nos exemplos exigem uma nova versão; isso preserva a rastreabilidade do treinamento.

03
Estrutura

Entenda o contrato LAYA

state

Contexto factual que o modelo deve analisar.

questions

Perguntas, tipo de resposta, instruções, critérios e labels permitidos.

gold

Resposta esperada usada como referência durante o treinamento.

TipoQuando usarO que validar
choiceEscolha entre alternativas.Labels, critérios e resposta pertencente às opções.
scoreNota ou probabilidade numérica.Faixa permitida e precisão coerente.
noulSaída estruturada ou ausência de resposta.Formato, campos e condição de valor nulo.
Dica

Critérios objetivos reduzem ambiguidades. Escreva o que diferencia cada label em vez de apenas repetir o nome dela.

04
Fine-tuning

Treine com rastreabilidade

Na tela Treinamentos, escolha um dataset e uma versão. A pré-validação impede o envio quando há problemas de contrato. O executor prepara o JSONL, envia o kernel fixado ao Kaggle e acompanha os estados reais até baixar e validar o checkpoint.

  1. Confirme que a versão contém exemplos suficientes e válidos.
  2. Execute a pré-validação e corrija todos os itens vermelhos.
  3. Inicie a execução e acompanhe os logs de preparação, upload e treinamento.
  4. Espere a validação do checkpoint; conclusão do notebook, sozinha, não comprova um modelo utilizável.
Atenção

Não altere ou substitua o JSONL depois de criar a versão. O hash da versão é a evidência de quais dados produziram o modelo.

05
Runtime

Publique, baixe e ative modelos

Checkpoints validados são publicados automaticamente em um repositório privado do Hugging Face. A tela Modelos reúne os artefatos locais e os modelos LAYA da conta conectada.

Regra de segurança operacional

Somente um modelo pode ficar ativo por vez. Pare o atual para liberar memória antes de iniciar outro.

Ao iniciar um modelo remoto, o modal mostra percentual, bytes, arquivo atual e carregamento. O cache persistente evita repetir downloads completos.

Dica

“No Hugging Face” confirma a publicação. “Em execução” confirma qual modelo o runtime local realmente carregou.

Abrir modelos
06
Uso

Teste uma inferência real

Com um modelo ativo, selecione Testar inferência. Informe um state e um objeto questions compatível com o contrato usado no treinamento. O resultado exibido vem diretamente do runtime LAYA.

Boa prática

Teste casos conhecidos, casos ambíguos e casos nunca vistos. Compare a resposta com os critérios definidos e registre falhas úteis como novos exemplos para uma versão futura.

07
Integrações

Credenciais e privacidade

As credenciais são guardadas somente nos volumes locais do aplicativo e nunca são devolvidas pela interface ou pela API. O Kaggle exige uma credencial válida para executar notebooks; o Hugging Face exige um token com escrita para publicar modelos.

Atenção

Nunca coloque tokens no dataset, README, logs, commits ou capturas de tela. Revogue imediatamente qualquer chave exposta.

Dica

Os repositórios de modelos são criados como privados. Revise permissões na conta antes de compartilhar um modelo.

Abrir configurações
08
Diagnóstico

Resolva problemas comuns

Abra Configurações, salve novamente a credencial e confirme o estado “Conectado”. Verifique também se a conta possui acesso ao kernel e disponibilidade de GPU.

Use um token Write. Ao salvar uma credencial válida, o aplicativo agenda novamente as publicações que falharam por autorização.

Pare o modelo ativo primeiro. Isso descarrega o agente atual e libera a memória antes do próximo carregamento.

Confirme que há um modelo ativo e que state e questions são JSON válido. As perguntas devem usar tipos e estruturas compatíveis com o treinamento.
Antes de investigar

Leia a mensagem mostrada na própria tela. O sistema preserva diagnósticos de importação, logs do treinamento, falhas de publicação e erros de carregamento exatamente na etapa correspondente.
